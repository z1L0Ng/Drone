\section{System Design}
\label{sec:system}

\subsection{Design Goals}

The system is organized around four goals:
\begin{itemize}
\item \textbf{Robustness under rotor noise.} The model should preserve useful intent information when the UAV itself is the dominant noise source.
\item \textbf{Emergency-aware behavior.} Missing an emergency command is more costly than missing a benign movement command, so per-class recall matters.
\item \textbf{Fully onboard execution.} Audio capture, inference, and dispatch should not depend on cloud ASR or network connectivity.
\item \textbf{Safe fallback behavior.} The system must reject uncertain inputs through an \emph{unknown} path instead of over-triggering commands.
\end{itemize}

\subsection{Architecture}

Figure-quality system diagrams should eventually show the following path:
\[
\text{Microphone} \rightarrow \text{Feature Frontend} \rightarrow \text{Intent Model} \rightarrow \text{Safety Logic} \rightarrow \text{Flight Controller}.
\]
Audio is captured onboard, segmented into short windows, converted into time-frequency features, and fed to a lightweight classifier. The classifier outputs one of three intent classes: \emph{emergency}, \emph{movement}, or \emph{unknown}. Downstream decision logic then applies confidence thresholds and dispatch rules before forwarding a command to the flight controller interface.

\subsection{Command Abstraction and Safety Logic}

The three-way taxonomy is central to the paper story.
\begin{itemize}
\item \textbf{Emergency} covers stop, hold, land, and similarly safety-critical utterances.
\item \textbf{Movement} covers ordinary navigation commands whose failure cost is lower.
\item \textbf{Unknown} captures off-task speech, uncertain predictions, and unsupported utterances.
\end{itemize}

This abstraction gives the paper a systems argument that is stronger than a generic speech-recognition argument. The goal is not to transcribe arbitrary language onboard a drone; the goal is to decide when a small set of action classes can be trusted enough to enter a control loop.

\subsection{Deployment Boundary}

The current manuscript should assume a single onboard microphone and no external beamforming infrastructure. That keeps the claimed system boundary realistic for small UAV platforms. If future versions use additional microphones or offboard sensing, that should be presented as an extension rather than silently changing the problem definition.
