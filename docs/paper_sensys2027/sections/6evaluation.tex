\subsection{Evaluation Questions}

The evaluation is organized around the contracts introduced in Sections~\ref{sec:system}--\ref{sec:prototype}:
\begin{itemize}
\item \textbf{Emergency recognition:} Does the noisy intent recognizer preserve emergency interruption behavior under rotor-contaminated audio?
\item \textbf{Embedded feasibility:} Can the embedded student run as a local int8 TFLM voice-event source?
\item \textbf{Bridge auditability:} Does the control bridge log enough state to distinguish reject, hold, escalation, and forwarding decisions?
\end{itemize}

\subsection{Bridge and Gate Protocols}

The bridge evaluation will report command/state logs with predicted label, confidence, safety-state transition, selected command, send event, and acknowledgement or timeout. Emergency events should be distinguishable from movement and unknown events in the bridge log, and each event should produce an auditable state transition rather than an implicit command. The gate evaluation will report false-trigger behavior across silence, background, rotor-like noise, and speech-trigger cases. These protocols connect recognizer outputs to safety behavior without treating a classifier score as a flight result.
