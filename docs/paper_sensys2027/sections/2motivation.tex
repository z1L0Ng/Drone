\subsection{From Convenience Interface to Safety Layer}

Small drones increasingly operate close enough to people that interaction cannot be treated only as a convenience feature. A nearby person may need to interrupt a drone, redirect it, or de-escalate its behavior without a handset, specialist tooling, or a reliable network path. In that setting, speech is attractive because it is natural and immediate, but it is also fragile: the vehicle that should remain interruptible is itself a strong noise source.

This paper therefore frames drone speech control as a \emph{voice safety layer}. The layer is intentionally narrower than open-ended conversation. It maps short audio windows into a small set of operational intents, routes uncertain inputs to an explicit rejection path, and leaves final command dispatch to safety logic rather than to raw classifier output.

The motivation is consistent with prior UAV speech-interface work, which shows that spoken interaction with drones is feasible in principle \cite{oneata19_interspeech,oneata2021multimodal}, and with UAV-noise studies showing that drone operating noise can degrade voice-command discrimination \cite{miesikowska2021uavnoise,park2023uavvehicle}. Current European drone regulations also frame UAS deployment around safety, security, privacy, data protection, and operational responsibility \cite{eu2019uasops,eu2019uasdesign}. These sources motivate the problem, but the empirical claims in this draft are grounded in the repository results described in Section~\ref{sec:evaluation}.

\subsection{Why Intent-Level Modeling Fits the Drone Setting}

The system does not need to recover arbitrary transcripts. It needs to identify whether speech near a drone expresses an emergency action, an ordinary movement action, or an unsupported or uncertain utterance. Direct speech-to-intent modeling is a better fit for that objective than a transcript-first pipeline, and prior spoken language understanding work has shown that useful intent decisions can be learned directly from audio \cite{lugosch19_interspeech,kuo20_interspeech,mhiri20_interspeech}.

The repository evidence uses the same narrow abstraction: \emph{emergency}, \emph{movement}, and \emph{unknown}. This taxonomy is not a complete model of human-drone conversation. It is a conservative first interface for testing whether a drone can preserve safety-relevant intent recognition under rotor-like noise.

\subsection{Why Drone Noise Is the Main Technical Pressure}

Small drones combine limited onboard resources with severe self-noise. Rotor noise is close to the microphone, changes with propulsion state, and is not well represented by quiet indoor speech benchmarks. The key technical question is therefore not whether a speech model can work in clean audio. It is whether a compact intent recognizer can remain useful when training and evaluation explicitly include rotor-like interference.

The current writing should keep this pressure at the center. Cross-language and broader speaker-variation questions are useful motivation for why the abstraction should not be tied to a single phrase list, but they are not the main contribution of this draft. The current contribution is drone-centered: robust emergency-aware intent recognition under self-noise, with an ongoing path toward embedded execution.

\subsection{Scope of This Draft}

This draft does not claim that the full deployment problem is solved. The stable empirical anchor is the \texttt{w14} \texttt{preprocess\_ext} line, which provides the strongest reproducible noisy-set evidence currently selected for the paper. The ESP32/TFLM work is written as a deployment-constrained candidate path: it exposes concrete operator and memory limits, identifies \texttt{xiao\_bottleneck256\_tflm} as the next compatibility-oriented branch, and remains an ongoing convergence effort rather than a completed onboard result.
