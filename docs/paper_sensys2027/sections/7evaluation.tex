\section{Evaluation}
\label{sec:evaluation}

The evaluation follows the same layered structure as the system. First, we evaluate whether the acoustic recognizer separates emergency, movement, and unknown speech under rotor-noisy conditions. Second, we measure how that behavior changes as the acoustic setting becomes harder. Third, we test whether the embedded prototype can produce and report one intent-state update per one-second audio window. Fourth, we compare \sys{} with transcript-first ASR and compact speech-command classifier baselines. Fifth, we use offline safety-state ablations to measure how unsupported audio would leak into actionable states if speech labels were bound directly to action or if the unknown state were removed. Finally, we demonstrate the complete emergency-response loop in a controlled laboratory scene and measure participant-level recognition behavior during live onboard capture and inference.

This organization keeps each measurement tied to the claim it can support. Offline acoustic tests establish whether the intent-state mapping is learnable. Rotor-noise and recording-condition tests show how stable that mapping is when the acoustic setting changes. Embedded runtime measurements show whether the intent-state source can run near the drone. Transcript-first and compact classifier baselines test common speech-interface alternatives under the same rotor-noisy task. Safety-state ablations test why the unknown fallback and safety-state boundary matter before action. The emergency demonstration shows the integrated loop from local inference to mediated response in a constrained scene. Participant trials test how the embedded recognizer behaves on newly collected speech from different speakers.

At the fixed -10 dB SNR point, the offline acoustic reference model reaches 86.2\% accuracy and 0.862 macro F1, with emergency precision, recall, and F1 of 0.856, 0.859, and 0.857. For a safety interaction layer, that cost matters more than a single accuracy number. The current tables use argmax predictions; a thresholded operating curve would be needed to choose a specific emergency-recall versus unknown-containment point.

The embedded recognizer preserves high emergency precision but loses recall relative to the offline reference at the fixed -10 dB point. For a safety interaction layer, this means missed emergency speech is the more important embedded-model limitation, while false emergency or movement events from unsupported audio must be contained by the unknown path and the safety-state boundary. This connects model behavior to the intent-state mapping in Section~\ref{sec:system} without treating a single aggregate score as sufficient.

\subsection{Robustness Under Rotor Noise}

The second evaluation measures how recognition changes as rotor noise becomes more severe. The motivation is simple: a nearby UAV is not a static acoustic source. Rotor speed, drone state, and background sound can all change the mixture reaching the microphone. A single noisy-set score cannot show whether the recognizer degrades smoothly or fails under severe acoustic conditions.

The setup compares the same recognizer across controlled mixtures with locally recorded rotor-noise clips. Each condition uses the same label mapping and reports accuracy, macro F1, emergency recall, and the rate at which unknown audio is incorrectly turned into an actionable prediction. The robustness curve also records the noise source and mixing rule so that the sweep can be repeated when new acoustic recordings are added.

\subsection{Embedded Inference and Intent-State Reporting}

The third evaluation measures whether the embedded intent-state source can keep up with one-second audio windows near the UAV. Figure~\ref{fig:response_time_breakdown} shows the steady-state dual-core schedule used by the prototype. Core0 is dedicated to audio capture and keeps the microphone window cadence stable. Core1 consumes the completed window, computes the log-mel frontend, runs integer inference, and reports the resulting intent-state update. This overlap is the real-time optimization in the embedded path: after the first window is filled, capture for the next window proceeds while the previous window is being recognized, allowing the board to sustain one update opportunity per one-second audio window.

The timing supports the same interpretation as Figure~\ref{fig:response_time_breakdown}. Capture occupies the one-second audio window, while core1 spends 56 ms on log-mel feature extraction and 632 ms on integer inference for the previous window. This post-capture work fits behind the next capture window, so the prototype sustains a p50/p95 update period of 1005/1005 ms over 120 delivered windows, with no drops or overruns. The first update still appears after 1606 ms because the first capture must complete before recognition can begin. In the intended safety-layer deployment, the voice system starts with the UAV and remains active during operation, so the relevant operating condition is the steady-state update cadence rather than a cold first-window response. These measurements support steady-state real-time intent-state generation at the one-second window granularity; they do not claim that speech directly produces a vehicle-facing action.

\subsection{Transcript-First ASR Baseline}

A natural alternative is to transcribe the audio first and then parse the transcript for command words. This baseline represents a transcript-first design: a general ASR model produces text from each fixed one-second rotor-noisy clip, and a deterministic parser maps the transcript into emergency, movement, or unknown. The purpose is not to prove that all ASR systems fail near drones. It tests whether a straightforward transcript-first pipeline is a good fit for the short, rotor-noisy, embedded safety-interaction setting used by this paper.

The transcript-first row in Table~\ref{tab:recognition_asr_comparison} reports the result for Whisper \texttt{tiny.en} plus the deterministic parser on the same fixed -10 dB SNR condition used by the reference recognizer. Transcript non-empty rate reports how often the ASR produced text. Keyword hit rate reports how often the parser found a command word in the transcript.

The transcript-first baseline performs poorly in this condition because the ASR stage often does not produce a usable command transcript from the noisy one-second clip. The result supports a narrow claim: for the fixed rotor-noisy clips in this evaluation, transcript-first parsing is not a strong baseline for the intent-state task. It should not be read as a general claim about every ASR model, longer audio context, microphone layout, or cloud-scale recognizer.

\subsection{Compact Speech-Command Classifier Baselines}

The compact classifier evaluation compares \sys{} against small speech-command model families under the same task definition. The comparison is not meant to show that a larger speech architecture is universally better. It asks whether the proposed recognizer provides a better balance of noisy recognition quality, emergency recall, and unknown containment for the UAV safety interaction layer.

The comparison uses compact keyword-spotting or command-recognition baselines under a common train/test split, frontend budget, label mapping, and noisy evaluation condition. Each baseline reports recognition metrics such as accuracy, macro F1, emergency recall, and unknown false-action rate. The rows in Table~\ref{tab:baseline_comparison} use the same three-intent target and log-mel frontend, so the comparison focuses on recognizer behavior rather than task mismatch.

The interpretation focuses on acoustic quality under the shared three-intent task. A baseline needs to balance aggregate recognition quality, emergency recall, and false-action containment to be a strong fit for a safety interaction layer. BC-ResNet1 achieves higher emergency recall (0.90) at the cost of lower emergency precision: its reported emergency recall and F1 imply about 0.77 precision, producing more false emergency predictions. For a safety interaction layer, false emergency predictions create unnecessary interruptions and erode operator trust; the \sys{} reference recovers a better precision-recall balance (0.86/0.86) while also scoring higher on overall accuracy and macro F1.

Baseline fairness is especially important here. A generic keyword model trained on a different label mapping could look strong while avoiding the hardest part of the task: separating emergency speech from ordinary movement speech and unknown audio under rotor noise. The baseline rows above use the same three-intent target, split, log-mel frontend, and noisy evaluation condition. TC-ResNet8, BC-ResNet1, and DS-CNN-S are therefore compact speech-command classifier baselines. They are not complete safety-system baselines because they do not include the intent-state mapping, unknown fallback policy, embedded intent-state source, or safety-state boundary.

\subsection{Safety-State Boundary Ablations}

The safety-state ablations ask how unsupported or uncertain audio would be handled if recognizer outputs were treated as actions, or if the unknown fallback were removed. These are offline action-pressure simulations over existing predictions and confusion matrices. They are not flight tests and not measured UAV actuation. Their role is to quantify why the architecture keeps speech as a mediated intent-state stream instead of binding every recognized label directly to action.

Table~\ref{tab:safety_ablation} summarizes the direct-mapping and no-unknown ablations. The informative quantities are the unknown false action rate and the destination of true-unknown audio after the fallback is removed. The aggregate action-request counts are reported only as accounting context: with a balanced three-intent dataset, mapping emergency and movement to action naturally makes about two thirds of windows actionable, and removing unknown naturally drives the count to all windows.

The direct-mapping result shows why the safety-state boundary is not just an implementation detail. The main signal is not that roughly two thirds of a balanced three-intent set become actionable when emergency and movement are bound to action; that follows from the label structure. The useful observation is that unknown audio still leaks into action with a false action rate of 0.1634. The no-unknown ablation makes the containment problem sharper: for the embedded user-study predictions, true unknown audio would be forced mostly into emergency under the two-action ablation, which would create unnecessary safety-critical interruptions. These results support the architecture's conservative intent-state mapping; they do not establish any particular vehicle behavior as safe.

\subsection{End-to-End Emergency Demonstration}

The emergency demonstration exercises the complete interaction in a controlled laboratory scene. During the demo, the UAV remains in normal operation while the embedded recognizer continues to process onboard audio windows. When a nearby person speaks an emergency phrase, the voice layer emits an emergency intent-state update, the safety-state boundary mediates that update, and the vehicle transitions to a landing or stopped response rather than treating speech as an immediate movement action.

\begin{figure*}[t]
    \centering
    \includegraphics[width=\textwidth]{figures/emergency_stop_sequence.pdf}
    \caption{Controlled laboratory emergency-response demonstration. The panels show normal in-flight operation, nearby emergency speech while onboard inference remains active, and the resulting safe landing or stopped state through the mediated safety-state boundary.}
    \label{fig:emergency_stop_sequence}
\end{figure*}

Figure~\ref{fig:emergency_stop_sequence} is included as a system demonstration rather than as complete deployment evidence. It makes the paper's main interaction visible: local recognition continues while the drone is operating, emergency speech is converted into an intent-state update, and the response goes through the safety-state boundary before the UAV behavior changes. This is different from a conventional obstacle-avoidance stop, where the vehicle reacts only to objects or proximity. \sys{} adds a nearby human speech channel that can request safety-critical handling before the situation is reduced to a collision response.

The demonstration supports the end-to-end feasibility claim for the proposed interaction loop in a constrained lab setting. It should be read together with the recognition, runtime, and user-study measurements: the demo shows the integrated story, while the quantitative sections measure the pieces that must be reliable before making broader UAV safety claims.

\subsection{User Study}

The user study measures participant-level recognition robustness across different speakers, intent categories, keywords, and repeated trials using live onboard capture and inference with the embedded recognizer. Each participant is assigned a study identifier, and participant results are reported separately before aggregation. This isolation lets the evaluation report aggregate behavior while still exposing per-participant variation, which is important for a voice interface that may fail unevenly across speakers.

Each complete participant record contains three intent categories: emergency, movement, and unknown. Each category is represented by five controlled keywords or short phrases, with ten repeated trials for each keyword, for 150 trials per complete record. Unknown trials include unsupported or irrelevant speech, and may also include silence or background audio, so the class represents audio that should not become a command rather than silence alone. Table~\ref{tab:user_study_participant_variability} reports complete and partial participant records separately, so the reader can distinguish participant-level variation from missing prompt coverage.

These trials use the same onboard capture-to-inference path measured in Figure~\ref{fig:response_time_breakdown}, but they are counted as prompted utterance trials rather than as the continuous-window timing run.
